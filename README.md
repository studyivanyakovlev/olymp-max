# 🏆 Олимпиадный навигатор в MAX (Backend)

Серверная часть, движок напоминаний и интеграция с платформой MAX Bot API для решения «Олимпиадный навигатор в MAX».

Проект помогает школьникам 8–11 классов не упустить регистрацию и туры перечневых олимпиад РСОШ (1, 2, 3 уровней) и этапов ВсОШ, которые дают особые права при поступлении в вузы (**БВИ** или **100 баллов ЕГЭ**).

## ⚡ Быстрый старт (Локальная разработка)

Проект готов к работе прямо «из коробки». **Не требуется поднимать сторонний сервер PostgreSQL или Docker**: сервер оснащен встроенным движком PostgreSQL 16 (`PGlite`), который работает прямо в Node.js!

### 1. Установка зависимостей
```bash
npm install
```

### 2. Загрузка датасета олимпиад в базу
```bash
npm run seed
```
Команда проверит `data/olympiads.json` и `data/demo.json` на соответствие `data/schema.json` и наполнит базу данных.

### 3. Запуск симулятора пользовательских сценариев
```bash
npm run simulator
```
Симулятор автоматически прогоняет 10 сценариев:
- Ввод `/start`
- Интерактивный выбор 10 класса
- Мультивыбор предметов (Информатика, Математика) и нажатие «Готово»
- Выбор региона («Москва»)
- Формирование персонализированной подборки олимпиад
- Подписка на демо-олимпиаду
- Просмотр `/my` (дедлайны)
- Срабатывание планировщика и доставка напоминания
- Нажатие кнопки «Зарегистрировался» в напоминании и смена статуса подписки
- Проверка главного меню `/menu`

### 4. Запуск автотестов
```bash
npm test
```
Запускает модульные и интеграционные тесты (`vitest`): валидацию схемы датасета, алгоритм сдвига времени тихих часов (09:00–21:00), проверку HMAC-SHA256 подписи `initData` и логику кнопок напоминаний.

### 5. Запуск сервера разработки
```bash
npm run dev
```
После старта доступны:
- **HTTP REST API**: `http://localhost:3000`
- **Интерактивная Swagger OpenAPI документация**: `http://localhost:3000/docs`
- **Healthcheck**: `http://localhost:3000/api/health`

## 🧩 Подробное устройство компонентов

### 1. База данных (`src/db/`)
Спроектировано 8 нормализованных таблиц:
- `users`: ID в MAX (`max_user_id`), класс, код региона, часовой пояс, тихие часы (`quiet_from`, `quiet_to`), согласие на обработку данных.
- `user_subjects`: выбранные предметы школьника (для скоринга рекомендаций).
- `olympiads`: карточка олимпиады (название, организатор, уровень РСОШ 1–3, предметы, классы, льготы БВИ, ссылки на регламент).
- `stages`: этапы олимпиады (регистрация, отборочный тур, финал) с точными датами в ISO 8601 и форматом (online/offline).
- `subscriptions`: статус участия школьника (`interested`, `registered`, `done`, `dropped`).
- `reminders`: очередь напоминаний с защитой от дублей по ключу `(subscription_id, stage_id, kind)`, временем отправки `send_at` и статусом (`pending`, `sent`, `failed`, `cancelled`).
- `dialog_state`: шаг онбординга пользователя в боте (`onboarding_grade`, `onboarding_subjects`, `onboarding_region`, `ready`) и промежуточный выбор.
- `events`: аналитические события воронки для защиты кейса (клики, подписки, подтверждения регистраций).

### 2. Движок напоминаний и тихие часы (`src/domain/reminders.ts`)
- **Правило 1**: При подписке создаются напоминания:
  - `reg_start`: старт регистрации.
  - `reg_3d`: за 3 дня до закрытия регистрации.
  - `reg_1d`: за 1 день до закрытия регистрации.
  - `stage_1d`: за 1 день до каждого тура/финала.
  - Прошедшие даты автоматически отсекаются.
- **Правило 2 (Тихие часы)**: Время отправки сдвигается в окно активности `09:00–21:00` по часовому поясу региона пользователя и обходит его тихие часы (по умолчанию 22:00–08:00). Ночные дедлайны переносятся на 09:00 утра следующего дня.
- **Правило 5 (Интерактивные кнопки)**:
  - Кнопка «Зарегистрировался» отменяет регистрационные напоминания, переводит подписку в статус `registered` и сохраняет напоминания о предстоящих турах.
  - Кнопка «Напомнить завтра» создает новое персональное напоминание на `now + 24 часа`.
  - Кнопка «Не участвую» переводит подписку в `dropped` и отменяет все напоминания.
- **Правило 6 (Сдвиг дат)**: При повторном импорте датасета (`npm run seed`) система сравнивает даты этапов. Если дата изменилась, все неотправленные напоминания пересчитываются автоматически без создания дублей.
- **Правило 8 (Склейка)**: Не больше 3 напоминаний в сутки на пользователя.

### 3. Демо-режим для жюри (`src/domain/reminders.ts` + `data/demo.json`)
Чтобы эксперты жюри на защите могли оценить доставку напоминания за 1 минуту (а не ждать недели реальных дедлайнов):
- В каталоге есть `⚡ Демо-олимпиада MAX 2026 (для жюри и проверки)`.
- При нажатии кнопки «Подписаться» создается напоминание с типом `demo_1m` и временем `now() + 1 минута`.

### 4. Безопасность и `initData` (`src/domain/security.ts`)
Запросы от Mini App авторизуются без паролей:
- Клиент передает заголовок `x-init-data` со строкой параметров от MAX Bridge.
- Сервер вычисляет HMAC-SHA256 хеш с использованием секретного ключа бота:
  `secret_key = HMAC_SHA256("WebAppData", botToken)`
  `hash = HMAC_SHA256(secret_key, dataCheckString)`
- При несовпадении подписи возвращается `401 Unauthorized`.
- Для удобства локального тестирования и разработки фронтенда без MAX Bridge поддерживается dev-заголовок `x-user-id: <user_id>`.

### 5. Планировщик (`src/scheduler/index.ts`)
- Раз в минуту делает выборку пачки до 50 готовых к отправке напоминаний (`SELECT ... FOR UPDATE SKIP LOCKED` / транзакционная безопасность).
- Троттлинг: 20 сообщений в секунду (при лимите платформы 30 req/s).
- При сетевой ошибке делает повтор через 5 минут; после 3 неудачных попыток переводит статус в `failed` и логирует ошибку.

### 6. REST API для Mini App (`src/api/routes.ts`)
| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/health` | Проверка состояния сервиса и базы данных |
| `GET` | `/api/olympiads` | Каталог с фильтрами `subject`, `grade`, `level`, `search` |
| `GET` | `/api/olympiads/:id`| Полная карточка олимпиады со всеми этапами |
| `GET` | `/api/me` | Профиль ученика (класс, предметы, регион, тихие часы) |
| `PUT` | `/api/me` | Обновление настроек профиля ученика |
| `DELETE` | `/api/me` | Полное удаление всех данных ученика (право на забвение) |
| `GET` | `/api/me/subscriptions` | Мои олимпиады с ближайшим дедлайном |
| `POST` | `/api/me/subscriptions` | Оформить подписку и сгенерировать напоминания |
| `PATCH` | `/api/me/subscriptions/:id` | Сменить статус (`registered` / `dropped` / `interested`) |

## 🛠 Руководство: Как дорабатывать любой кусок

### Как добавить или изменить олимпиады
1. Откройте `data/olympiads.json`.
2. Добавьте объект олимпиады со списком этапов (все даты указываются в ISO 8601 с таймзоной, например `2026-10-15T09:00:00+03:00`).
3. Запустите `npm run seed`. Если какое-то обязательное поле пропущено, валидатор JSON Schema сразу подскажет точное имя поля.

### Как изменить логику диалога или онбординга
1. Кнопки и разметка находятся в `apps/server/src/bot/keyboards.ts`. Чтобы добавить новую кнопку или изменить текст — правьте соответствующий метод (например, `gradeKeyboard()`, `subjectsKeyboard()`, `mainMenu()`).
2. Тексты сообщений и обработка шагов диалога находятся в `apps/server/src/bot/handlers.ts`. Шаг онбординга отслеживается через поле `step` в таблице `dialog_state`.

### Как подключить реального бота в платформе MAX
1. Получите токен бота у организаторов / в BotFather MAX.
2. Скопируйте `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
3. Укажите полученный токен:
   ```env
   BOT_TOKEN=ваш_настоящий_токен_max
   BOT_MODE=polling
   ```
4. Запустите сервер:
   ```bash
   npm run dev
   ```
   Бот начнет получать реальные сообщения и нажатия кнопок от пользователей MAX через long-polling.

## 🚀 Развёртывание в Docker на боевом сервере (VPS)

Для развертывания на боевом сервере с автоматическим получением бесплатного SSL-сертификата (HTTPS через Let's Encrypt):

1. В `.env` укажите домен и боевой токен:
   ```env
   BOT_TOKEN=настоящий_токен
   BOT_MODE=webhook
   PUBLIC_URL=https://olymp-bot.yourdomain.ru
   PUBLIC_DOMAIN=olymp-bot.yourdomain.ru
   ```
2. Запустите стек одной командой:
   ```bash
   docker compose up -d --build
   ```
   Поднимутся три контейнера:
   - `olymp_max_db`: PostgreSQL 16 с персистентным томом `postgres_data`
   - `olymp_max_app`: скомпилированный бэкенд-сервер на Node.js 22
   - `olymp_max_caddy`: веб-сервер Caddy, выпускающий HTTPS-сертификат и проксирующий запросы к API и вебхукам
